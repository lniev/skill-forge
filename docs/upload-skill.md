# 上传 Skill 页面产品文档

## 一、背景与目标

Skill 管理平台需要给 Skill 作者提供一个低门槛的 Skill 上传入口。当前平台已经支持从 Marketplace 浏览和安装 Skill，但缺少由用户主动上传 Skill 的能力。

Skill 文档本身可以在任意 AI 工具（如 Claude、ChatGPT、Kimi 等）中通过对话方式生成，生成本地文件后，再到本平台完成上传、管理和发布。

本页面旨在解决以下场景：

- 用户已经有一个写好的 Skill Markdown 文档，希望直接上传到平台
- 用户有一个完整的 Skill 项目文件夹，希望打包上传
- 用户在第三方 AI 工具中生成了 Skill 文档，希望上传到平台进行管理和发布
- 未来希望支持更复杂的 Skill：包含附件资源、代码脚本、评测数据集等

## 二、页面定位

- **入口**：Skill 管理平台顶部导航或 Marketplace 右上角，提供「上传 Skill」按钮
- **目标用户**：Skill 作者、内部开发者、AI 工具维护者
- **核心价值**：让 Skill 的上传、校验、发布变得简单、标准化、可扩展

## 三、上传方式

页面只提供 **本地上传** 入口。用户在其他 AI 工具中完成 Skill 文档创作后，将文件上传到本平台。

### 3.1 支持的文件格式

| 格式 | 说明 | 处理逻辑 |
|---|---|---|
| `.md` 文件 | 单文件 Skill 描述文档 | 直接解析文件内容，提取元数据和正文 |
| `.zip` 压缩包 | 包含 Skill 文档和可能的资源文件 | 解压后识别目录结构，提取主文档和附件 |

### 3.2 上传流程

1. 用户点击「上传 Skill」按钮进入上传页面
2. 进入拖拽区域，支持点击选择文件或拖拽上传
3. 系统根据文件类型处理：
   - `.md` → 解析 frontmatter，进入元信息编辑页
   - `.zip` → 解压并分析目录结构，进入元信息编辑页
4. 用户补充/确认元信息
5. 用户点击「发布」或「保存为草稿」

### 3.3 文件解析规则

对于 Markdown 文件，需要支持解析 frontmatter：

```markdown
---
name: "邮件意图分类"
id: "email-classifier"
version: "1.0.0"
author: "fde-team"
category: "nlp/classification"
tags: ["email", "classification", "customer-service"]
---

# 邮件意图分类

自动识别邮件意图：咨询、投诉、售后、合作等。

## 输入

...
```

如果 frontmatter 缺失或字段不完整，进入元信息编辑页面让用户补充。

对于 ZIP 压缩包，期望目录结构：

```
my-skill/
├── skill.md              # 主文档（必须）
├── prompt.txt            # 提示词资源（可选）
├── eval/                 # 评测数据集（可选）
│   └── dataset.jsonl
└── icon.png              # 图标（可选）
```

系统识别 `skill.md` 作为主文档，其他文件作为附件资源。

## 四、元信息编辑

上传文件后，用户需要确认或补充以下元信息：

| 字段 | 必填 | 说明 |
|---|---|---|
| Skill 名称 | 是 | 展示名称 |
| Skill ID | 是 | 唯一标识，URL 友好 |
| 版本 | 是 | 默认 `1.0.0`，遵循 SemVer |
| 作者 | 是 | 作者或团队 |
| 分类 | 是 | 如 NLP/分类、文本生成、信息提取 |
| 标签 | 否 | 多个标签 |
| 图标 | 否 | 上传或选择默认图标 |
| 一句话描述 | 是 | 简短描述 |
| 详细描述 | 是 | 功能说明 |
| 运行时类型 | 是 | llm_prompt / python_script / api_call / workflow |
| 输入定义 | 是 | 字段名、类型、必填、默认值、说明 |
| 输出定义 | 是 | 字段名、类型、说明 |
| 运行时配置 | 是 | 模型、温度、资源文件等 |
| 依赖 | 否 | 依赖的其他 Skill |
| 权限 | 否 | 所需权限列表 |
| 评测标准 | 否 | 准确率、延迟等指标 |
| 可见性 | 是 | public / private / team |

## 七、Skill 文档生成说明

本平台 **不负责** 通过 AI 对话生成 Skill 文档。用户应使用自己熟悉的 AI 工具完成文档创作，例如：

- Claude
- ChatGPT
- Kimi
- Cursor
- 其他支持对话生成的 AI 工具

生成后的文档需要符合本平台的标准格式，然后通过本页面上传。

### 推荐在其他 AI 工具中使用的 Prompt

```
请帮我生成一个符合以下标准的 Skill 文档：

1. 使用 Markdown 格式
2. 顶部包含 frontmatter：name, id, version, author, category, tags
3. 明确输入输出定义
4. 运行时配置使用 YAML 代码块
5. 包含使用示例

Skill 名称：{name}
功能描述：{description}
运行时类型：{runtime_type}
```

## 八、后续扩展：文件附件与代码附件

### 8.1 文件附件

未来支持用户上传以下资源文件：

| 附件类型 | 说明 |
|---|---|
| Prompt 模板文件 | `.txt`、`.md`、`.jinja` |
| 图标 | `.png`、`.jpg`、`.svg` |
| 评测数据集 | `.jsonl`、`.csv` |
| 说明文档 | `.md`、`.pdf` |

上传方式：

- 本地上传 ZIP 时自动识别
- 在线编辑时通过「添加附件」按钮手动上传

### 8.2 代码附件

未来支持上传代码脚本：

| 类型 | 文件 |
|---|---|
| Python 脚本 | `main.py` |
| JavaScript 脚本 | `index.js` |
| 工作流定义 | `workflow.yaml` |
| 依赖配置 | `requirements.txt`、`package.json` |

代码附件需要在运行时由 Runtime 加载，并在沙箱环境中执行。

### 8.3 附件管理

上传后的附件统一由后端对象存储管理，Skill 文档中通过相对路径引用：

```yaml
assets:
  - type: prompt
    path: "prompt_v1.txt"
  - type: script
    path: "main.py"
  - type: eval
    path: "eval/dataset.jsonl"
```

## 十、API 依赖

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/skills` | 创建 Skill（草稿/发布） |
| `POST` | `/api/skills/:id/versions` | 发布新版本 |
| `POST` | `/api/skills/:id/versions/:version/assets` | 上传附件资源 |

## 十一、验收标准

- [ ] 用户可以通过拖拽或点击上传 `.md` 文件
- [ ] 用户可以通过拖拽或点击上传 `.zip` 文件
- [ ] 系统能正确解析 Markdown frontmatter
- [ ] 系统能正确解压并识别 ZIP 内的主文档和附件
- [ ] 元信息不完整时，自动进入元信息编辑模式
- [ ] 用户可以通过表单填写/修改元信息
- [ ] 用户可以预览解析后的 Skill 文档
- [ ] 用户可以保存为草稿或发布
- [ ] 发布后可以在仓库列表中看到该 Skill
