# 用户管理页面产品文档

## 一、背景与目标

随着 Skill Platform 引入用户体系，平台需要一个集中管理用户的入口，供管理员查看、审核、禁用、删除用户账号，并分配角色与权限。

「用户管理」页面用于解决以下问题：

- 查看平台所有注册用户
- 管理用户状态（启用 / 禁用 / 删除）
- 分配和调整用户角色
- 重置用户密码
- 查看用户创建的 Skill 统计

## 二、页面定位

- **入口**：左侧 Sidebar 仅对 `admin` 角色展示「用户管理」
- **目标用户**：平台管理员
- **核心价值**：统一维护平台用户，保障平台安全与秩序

## 三、入口设计

在左侧 Sidebar 的「Getting Started」分组中仅对管理员显示「用户管理」：

```
Getting Started
├── Overview
├── Skills                 # Skill 市场
├── 我的技能              # 已登录用户
├── CLI
├── MCP server
├── 用户管理              # 仅 admin 可见
```

路由：

```ts
export const routePaths = {
  // ...
  userManagement: "/users",
} as const;
```

## 五、用户状态

| 状态 | 说明 | 可执行操作 |
|---|---|---|
| `active` | 已启用，可正常登录和使用 | 禁用、编辑、重置密码、删除 |
| `inactive` | 已禁用，无法登录 | 启用、删除 |
| `pending` | 待审核，注册后未激活 | 通过、拒绝、删除 |
| `deleted` | 已删除（软删除） | 恢复（可选）、彻底删除 |

## 六、用户角色

| 角色 | 说明 | 权限 |
|---|---|---|
| `user` | 普通用户 | 创建、管理自己的 Skill |
| `admin` | 管理员 | 用户管理、审核 Skill、系统配置 |

角色可扩展为更细粒度的 RBAC 模型（后续）。

## 七、用户表格字段

| 字段 | 说明 |
|---|---|
| 头像 | 用户头像或默认头像 |
| 用户名 | 展示名称 |
| 邮箱 | 登录邮箱 |
| 角色 | user / admin |
| 状态 | active / inactive / pending / deleted |
| 注册时间 | 首次注册时间 |
| 最后登录时间 | 最近登录时间 |
| Skill 数量 | 该用户创建的 Skill 数，可点击跳转 |
| 操作 | 编辑 / 禁用 / 启用 / 重置密码 / 删除 |

## 八、操作说明

### 8.1 新建用户

管理员手动创建账号：

- 用户名
- 邮箱
- 初始密码（或发送随机密码到邮箱）
- 角色
- 状态

### 8.2 编辑用户

可修改：

- 用户名
- 角色
- 状态
- 备注

### 8.3 禁用/启用

- **禁用**：用户无法登录，已登录的 token 立即失效
- **启用**：恢复用户登录权限

### 8.4 重置密码

- 管理员触发后，系统发送重置链接到用户邮箱
- 或生成随机初始密码，要求首次登录修改

### 8.5 删除用户

- **软删除**：标记为 `deleted`，保留数据，不可登录
- **彻底删除**：物理删除数据（需二次确认，仅限超级管理员）

## 九、筛选与搜索

### 9.1 状态筛选

Tab 形式：

- 全部
- 已启用
- 已禁用
- 待审核
- 已删除

### 9.2 搜索

按用户名、邮箱、用户 ID 搜索

### 9.3 角色筛选

下拉筛选：全部 / user / admin

### 9.4 排序

- 最近注册
- 最近登录
- 用户名 A-Z

## 十、数据流转

```
管理员进入「用户管理」页面
    │
    ▼
前端调用 GET /api/users
    │
    ▼
后端返回用户列表（支持分页、搜索、筛选）
    │
    ▼
前端展示用户表格
    │
    ▼
管理员执行操作：
    ├── 新建 → POST /api/users
    ├── 编辑 → PATCH /api/users/:id
    ├── 禁用 → PATCH /api/users/:id (status -> inactive)
    ├── 启用 → PATCH /api/users/:id (status -> active)
    ├── 重置密码 → POST /api/users/:id/reset-password
    └── 删除 → DELETE /api/users/:id
```

## 十一、API 依赖

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/users` | 获取用户列表 |
| `GET` | `/api/users/:id` | 获取用户详情 |
| `POST` | `/api/users` | 新建用户 |
| `PATCH` | `/api/users/:id` | 更新用户信息/状态/角色 |
| `DELETE` | `/api/users/:id` | 删除用户 |
| `POST` | `/api/users/:id/reset-password` | 重置用户密码 |
| `GET` | `/api/users/:id/skills` | 获取用户创建的 Skill 列表 |

## 十二、权限与安全

- 只有 `admin` 角色可以访问「用户管理」页面
- 后端接口必须校验 `admin` 权限
- 禁止管理员删除自己的账号
- 删除管理员账号前需要二次确认
- 操作日志记录：谁、何时、对谁、做了什么操作

## 十三、与现有系统的关系

| 模块 | 影响 |
|---|---|
| `Layout` | Sidebar 增加「用户管理」入口，仅 admin 可见 |
| `routes/index.tsx` | 增加 `/users` 路由，配置 admin 权限守卫 |
| `authStore` | 登录后保存用户角色，用于前端路由和菜单控制 |
| `MySkills` | 管理员可从用户管理页跳转查看某用户的 Skill |
