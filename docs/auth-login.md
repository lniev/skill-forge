# 用户登录与认证产品文档

## 一、背景与目标

当前 Skill Platform 桌面端尚未接入用户体系，所有页面默认以匿名状态访问。随着「我的技能」「用户管理」等功能的引入，平台需要统一的用户身份认证能力，以支持：

- 区分 Skill 作者与平台管理员
- 保护用户私有 Skill 资产
- 支持多租户/多角色权限控制
- 为后续付费、邀请、审计等功能奠定基础

## 二、设计原则

- **最小侵入**：桌面端仍以本地使用为主，登录态默认持久化，减少频繁登录打断
- **安全优先**：Token 不过期不下发长期凭证，敏感操作二次校验
- **可扩展**：认证协议支持本地账号、OAuth、SSO 等多种方式
- **离线可用**：核心功能在离线状态下仍可查看本地缓存数据

## 三、登录方式

### 3.1 账号密码登录（MVP）

- 用户名 / 邮箱 + 密码
- 支持「记住我」：本地安全存储 refresh token
- 登录失败次数限制，防止暴力破解

### 3.2 邮箱验证码登录

- 输入邮箱 → 发送验证码 → 输入验证码登录
- 适用于忘记密码或快捷登录场景

### 3.3 OAuth / SSO（后续）

- GitHub / GitLab / Google / 企业微信 / 钉钉等
- 由后端实现 OAuth callback，桌面端通过 Deep Link 或内嵌浏览器完成授权

### 3.4 本地访客模式（可选）

- 未登录时以访客身份使用
- 访客数据保存在本地，登录后可选择合并到账号

## 五、页面结构

### 5.1 登录页 (`/login`)

独立于 `Layout` 的全屏页面，包含：

| 元素 | 说明 |
|---|---|
| 品牌 Logo | 平台标识 |
| 登录表单 | 账号/密码或邮箱/验证码 |
| 记住我 | 控制 refresh token 持久化 |
| 忘记密码 | 跳转到找回密码页 |
| 注册入口 | 跳转到注册页 |
| 错误提示 | 用户名或密码错误、账号禁用等 |

### 5.2 注册页 (`/register`)

| 字段 | 说明 |
|---|---|
| 用户名 | 唯一，用于展示 |
| 邮箱 | 唯一，用于登录和找回密码 |
| 密码 | 强度校验 |
| 确认密码 | 与密码一致 |
| 验证码 | 邮箱验证码 |
| 服务协议 | 勾选后注册 |

### 5.3 找回密码页 (`/forgot-password`)

- 输入邮箱 → 发送验证码
- 输入新密码 → 确认新密码 → 提交重置

### 5.4 账号未激活/禁用提示页

- 账号未激活：提示检查邮箱激活链接
- 账号被禁用：联系管理员

## 六、状态与交互

### 6.1 登录状态

| 状态 | 说明 |
|---|---|
| `unauthenticated` | 未登录，访问需登录页面时重定向到登录页 |
| `authenticating` | 登录请求中，按钮显示 loading |
| `authenticated` | 已登录，可访问所有授权页面 |
| `token_refreshing` | 静默刷新 token 中 |

### 6.2 全局认证守卫

- 桌面端启动时检查本地 token
- 未登录时自动跳转到 `/login`
- 登录成功后跳转到之前访问的页面或默认首页 `/`

### 6.3 自动登出

- Token 过期且刷新失败时，跳转登录页
- 用户主动退出登录
- 修改密码后，当前设备以外的 token 失效（可选）

## 七、Token 与存储策略

### 7.1 Token 类型

- **Access Token**：短期有效（如 15 分钟），存储在内存中
- **Refresh Token**：长期有效（如 7 天），安全存储在 Tauri 安全存储或本地加密文件中

### 7.2 存储位置

| 信息 | 存储位置 | 说明 |
|---|---|---|
| Access Token | 内存（Zustand / Context） | 避免 XSS 泄露 |
| Refresh Token | Tauri `secure_storage` | 加密持久化 |
| 用户信息 | 本地 SQLite / 本地存储 | 离线可用 |
| 登录状态 | Zustand | 响应式驱动 UI |

### 7.3 刷新机制

- Access Token 即将过期前自动刷新
- 多个并发请求遇到 401 时，只发起一次刷新，其余排队重试

## 八、用户角色与权限

### 8.1 角色定义

| 角色 | 说明 | 权限 |
|---|---|---|
| `visitor` | 访客 | 浏览公开 Skill，无法创建/管理 |
| `user` | 普通用户 | 创建、管理自己的 Skill |
| `admin` | 管理员 | 用户管理、审核 Skill、系统配置 |

### 8.2 权限控制

- 前端路由级别：未登录无法访问 `/my-skills`、`/skills/upload` 等
- 组件级别：管理员可见「用户管理」入口
- API 级别：后端校验 token 和角色

## 九、API 依赖

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/auth/login` | 账号密码登录 |
| `POST` | `/api/auth/login/email` | 邮箱验证码登录 |
| `POST` | `/api/auth/register` | 用户注册 |
| `POST` | `/api/auth/logout` | 退出登录 |
| `POST` | `/api/auth/refresh` | 刷新 access token |
| `POST` | `/api/auth/forgot-password` | 发送找回密码验证码 |
| `POST` | `/api/auth/reset-password` | 重置密码 |
| `GET` | `/api/auth/me` | 获取当前登录用户信息 |

## 十、与现有系统的关系

| 模块 | 影响 |
|---|---|
| `Layout` | 顶部/侧边栏展示当前用户头像、名称；管理员显示「用户管理」入口 |
| `routes/index.tsx` | 增加 `/login`、`/register`、`/forgot-password` 等路由；主布局增加认证守卫 |
| `services/skills` | 请求自动携带 access token；401 时触发刷新或跳转登录 |
| `MySkills` | 必须登录后才能访问，默认只返回当前用户的 Skill |
| `SkillDetail` | 未登录时隐藏「编辑/删除」等私有操作 |

## 十二、验收标准

- [ ] 未登录时访问受保护页面自动跳转到登录页
- [ ] 支持账号密码登录和注册
- [ ] 登录成功后保存 token 并跳转首页
- [ ] Token 过期后自动刷新，刷新失败跳转登录页
- [ ] 登录页展示品牌 Logo 和错误提示
- [ ] 管理员在 Sidebar 看到「用户管理」入口
- [ ] 退出登录后清除本地 token 并跳转登录页
- [ ] 密码输入框支持显示/隐藏切换
